# ADR 0002: Obsidian Vault как локальная база знаний и панель синхронизации агентов

- Status: Accepted
- Date: 2026-09-03
- Scope: Архитектурный интерфейс для вайбкодинга, управления контекстом и взаимодействия Hermes-агентов

## Context

Разработка USNEE ведется с участием человека (продуктовые решения, вайбкодинг) и автономных AI-агентов (Hermes, Claude Code). Хранение проектных знаний и архитектурных решений только во временных чатах или разрозненных markdown-файлах приводит к потере контекста при смене сессий. 

Было необходимо организовать единое локальное пространство знаний («общий стол»), удовлетворяющее условиям:
1. Полная автономность и независимость от платных облачных сервисов (Obsidian Sync / Publish не используются).
2. Нативная интеграция с Git репозитория (директория `usnee/docs/vault/`).
3. Изоляция чувствительных данных (конфиденциальные API-ключи, внутренние настройки плагинов) от попадания в публичный репозиторий.
4. Двусторонний доступ: человек работает через десктопный GUI Obsidian, Hermes-агент взаимодействует через локальный API-сервер (:8642) и прямой доступ к markdown/canvas-файлам.

## Decision

1. **Размещение Vault**:
   Создана папка `usnee/docs/vault/`, содержащая канонические заметки (`HOME.md`, `архитектура.md`, `roadmap.md`, `агенты.md`, `решения.md`, `screen-states.md`, интерактивный `архитектура.canvas`).

2. **Граница секретов и .gitignore**:
   Файлы настроек плагинов, содержащие runtime-секреты и сессионные данные (`docs/vault/.obsidian/plugins/*/data.json`, `history.json`, `workspace*`), строго добавлены в `.gitignore`. Конфигурация плагинов (`community-plugins.json`) отслеживается в git.

3. **Стек плагинов Obsidian**:
   - `hermes-agent`: мост к локальному Hermes API (:8642) для диалога и анализа заметок прямо из интерфейса.
   - `agentfiles`: локальный аудит навыков и инструментов.
   - `hermes-tts`: генерация озвучки на базе edge-tts/Web Speech без внешних зависимостей.
   - `dataview`: динамические сводки и DQL-таблицы по фазам и статусам задач.
   - `templater` & `obsidian-git`: автоматизация создания сущностей и локальный контроль версий.

4. **Автономный контур верификации**:
   - Запущен локальный cron (15 минут), выполняющий watchdog-проверку сервисов и генерацию чек-поинтов в Telegram.
   - Hermes API сервер активен на порту 8642 с Bearer-авторизацией.

## Consequences

- Положительные:
  - Единый источник правды по архитектуре для разработчика и агентов.
  - Нулевая стоимость инфраструктуры синхронизации (используется Git + Syncthing).
  - Бесшовное продолжение задач в новых сессиях Hermes благодаря структурированному vault.
- Ограничения:
  - При ручном добавлении новых плагинов необходимо проверять их `data.json` на наличие токенов и следить за `.gitignore`.
