# Ранняя версия USNEE в Telegram

## Публичный URL

```text
https://adamfolz.github.io/usnee-app/
```

## Что работает

- Telegram Mini App bootstrap (`ready`, `expand`, цвета WebView из `themeParams` с фолбэком);
- Telegram BackButton на экране записи и поверх открытых sheet/dialog;
- closing confirmation на экране записи, пока черновик не сохранён;
- deep links из `start_param` (таблица ниже);
- Quick Record (расширенная форма пока вне роута `/add`);
- локальное атомарное сохранение в IndexedDB;
- History с честными локальными/sync-статусами;
- Прогресс: XP/уровни, недельный ритм и сводка за 7/30 дней и всё время;
- offline outbox для будущей отправки на backend.

## Deep links (start_param)

Приложение работает на HashRouter, маршруты вида `#/add`. Параметр `start_param`
читается один раз при старте и заменяет корневой `#/` на целевой маршрут
(`replace`, без записи в историю). Если пользователь открыл ссылку с явным
глубоким hash — он не перезаписывается.

Источник значения: `initDataUnsafe.start_param`, иначе query-параметр
`tgWebAppStartParam`. Неизвестное значение или отсутствие параметра — `#/`.

| start_param | Маршрут |
| --- | --- |
| `add`, `record` | `#/add` |
| `history` | `#/history` |
| `safety`, `sos` | `#/safety` |
| `progress`, `stats` | `#/progress` |
| `settings` | `#/settings` |

## Тема и закрытие WebView

- Если Telegram передаёт `themeParams`, цвет header берётся из
  `secondary_bg_color` (fallback `bg_color`), фон — из `bg_color`
  (fallback `secondary_bg_color`). Без `themeParams` — `#0b0d1a`.
- На экране записи включается native closing confirmation, пока черновик
  не сохранён. После успешного сохранения и при уходе с экрана — выключается,
  чтобы confirmation не блокировал закрытие пустого приложения.

## Текущие ограничения

- backend transport ещё не подключён;
- операции в outbox не отправляются на сервер и остаются в статусе ожидания;
- Telegram `initData` пока не отправляется и не валидируется сервером;
- данные принадлежат конкретному Telegram WebView/устройству;
- очистка данных Telegram или браузера удалит локальную историю без серверной копии;
- Safety Hub не входит в текущий рабочий срез.

## Границы приватности текущего среза (честно)

- PIN (4 цифры) блокирует интерфейс, но не шифрует хранилище. Это защита
  «от чужих глаз» на устройстве, а не криптографический периметр: счётчик
  попыток и вайп живут в локальном сторе и обходятся через devtools.
  Серверная защита лимита попыток появится вместе с backend.
- Экспорт шифруется AES-256-GCM (PBKDF2-SHA256, 250k итераций). При импорте
  конверт проверяется: допускается только формат `usnee-export-aes`,
  KDF `PBKDF2-SHA256` и число итераций в диапазоне 50k–1M.
- Если шифрование экспорта невозможно (например, WebCrypto недоступен вне
  HTTPS), экспорт **прерывается с ошибкой** — приложение никогда не тихо
  выгружает данные в открытом виде. Открытый JSON возможен только если
  поле пароля было осознанно оставлено пустым.
- Активная сессия NORS-чекина не переживает закрытие WebView: если Mini App
  был свёрнут во время check-in, emergency-экран не восстановится
  (запланировано к исправлению вместе с Safety Hub).

## Подключение через BotFather

1. Открыть BotFather и выбрать нужного бота.
2. Настроить Menu Button или Mini App.
3. Указать URL `https://adamfolz.github.io/usnee-app/`.
4. Открыть приложение именно из Telegram и проверить:
   - onboarding;
   - Quick Record;
   - повторное открытие WebView;
   - сохранность History;
   - Прогресс (сводка переехала сюда, `/stats` редиректит);
   - deep link `start_param=record` открывает экран записи;
   - Telegram BackButton.

BotFather и токен бота не хранятся в frontend-репозитории.
